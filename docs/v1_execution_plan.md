# 微撩 Flutter 1.0 重构执行方案

## 1. 目标与边界

1.0 的目标不是一次性补齐生产后端，而是在现有 Flutter 业务基础上完成一条可演示、可测试、可继续迭代的客户端闭环：

`首页发现活动 -> 创建/查看活动 -> 找搭子/查看个人主页 -> 发消息/聊天 -> 我的资料与资产`

本轮采用本地 Repository、Mock 数据和现有持久化能力。真实 IM、推送、登录、审核、举报处理、客服投递、跨设备同步、IAP 服务端验签不在一小时客户端骨架范围内，也不使用“永远成功”的假接口伪装生产闭环。

## 2. 已确认基线

- 技术栈：Flutter 3.35.7、Dart 3.9.2、GetX、Repository 分层、SharedPreferences。
- 现有模块：Home/Team、Square/Video、Chat/Voice Call、Profile、Wallet/VIP/IAP、UGC 与治理入口。
- 自动化基线：`flutter analyze` 0 问题；`flutter test` 20 项全部通过。
- Figma 来源：文件 `sZdTOBC0a94JYUYKgAJr8e`，页面“微撩重构”。用户给出的节点 `2039:14673` 是首页 Hero 内的装饰图，所在完整首页画板为 `1960:13484`。

## 3. 1.0 信息架构

底部导航按重构稿统一为：

1. 首页：附近搭子 Hero、推荐头像、活动列表、创建活动。
2. 找搭子：附近/新人/推荐用户，进入个人主页。
3. 广场：关注/发现/视频内容流，点赞、关注、预览和治理入口。
4. 消息：会话列表、系统消息、关系/访客/通话记录、单聊。
5. 我的：资料、微撩币、会员、相册、动态、客服与法律入口。

## 4. 关键流程与验收

### 活动流程

- 首页活动卡可进入详情。
- 创建活动可选择类型、填写必要字段、选择图片并提交。
- 提交后进入待审核结果并能返回首页看到本地持久化结果。
- 活动详情保留加入、VIP 门槛、发起人主页与攻略入口。

### 社交流程

- 找搭子列表可进入个人主页。
- 个人主页可关注/邀请、发消息、发起模拟通话、举报/拉黑/屏蔽。
- 广场支持关注/发现/视频切换及现有点赞、预览交互。

### 消息流程

- 消息页可进入普通会话和助手会话。
- 文本可发送，助手可本地回复，历史可恢复。
- 系统消息、亲密关系、谁看过我、通话记录提供可达的轻量页面骨架。

### 个人中心流程

- 资料修改、兴趣/标签、相册、动态发布和删除可持久化。
- 微撩币、会员和恢复购买继续复用现有 StoreKit 客户端链路。
- 客服、举报、隐私和用户协议保留明确入口。

## 5. 设计落地规则

- 画布基准为 375pt iPhone，使用 `SafeArea` 和滚动容器适配小屏。
- 主色使用 Figma 的暖黄 `#FFCE45`，正文 `#333333`，次级文字 `#999999`，卡片白色，弱背景采用暖白色。
- 卡片圆角以 12–20pt 为主，主要 CTA 使用深棕/暖黄高对比组合。
- 复用现有图片、头像、图标和业务组件；Figma 临时资源链接不直接进入长期代码。
- 五个主页面以 375×812 完整画板为布局权威，组件集只作为组件与状态资产权威；主结构、首屏坐标、内容密度和底栏必须逐屏截图验收。
- 设计稿中的头像、封面、装饰与图标下载为本地原始资产；不得把 Figma 临时 URL、Material 图标近似或 AI 生成图替代进成品。
- 新页面必须有空态、加载失败或不可用提示；不能留下空回调和“Coming soon”。

## 6. 并行任务与文件所有权

| 并行任务 | Figma 画板 | 独占目录 | 输出 |
|---|---|---|---|
| 首页活动闭环 | 首页、发布、活动详情 | `lib/modules/home/**` | 活动发现、创建、详情、加入 |
| 广场找搭子个人页 | 广场、广场-视频、搭子、个人主页 | `lib/modules/discover/**`、`lib/modules/user_detail/**` | 内容发现、找人、个人主页 |
| 消息聊天闭环 | 消息、聊天、系统/关系/访客/通话记录 | `lib/modules/chat/**` | 会话、单聊、消息支线 |
| 我的与资料支线 | 我的、充值、编辑资料、动态、相册、客服 | `lib/modules/profile/**` | 个人中心和资产/UGC支线 |
| 主控整合 | 五 Tab、主题、路由、资产、测试 | 共享层与测试 | 冲突消解、回归、成品验收 |
| View 视觉审核 | 用户已于 2026-09-04 暂停 | 不修改 App 代码 | 本轮不执行，不以旧结论覆盖用户布局 |

并行任务不得修改其他任务目录，不执行全项目格式化，不新增依赖。共享改动由主控统一完成。

## 7. 一小时推进节奏

- 0–10 分钟：Figma 结构、工程基线和流程差距审计；冻结 1.0 范围。
- 10–40 分钟：四个业务模块并行落地；主控处理五 Tab 与共享规范。
- 40–50 分钟：汇总模块结果，解决编译/导航/视觉冲突。
- 50–60 分钟：`dart format`、`flutter analyze`、`flutter test`，输出剩余风险与人工验收清单。

## 8. 工具与技能流程

1. `figma-design-to-code`：每个业务画板先拉取设计上下文，再适配 Flutter，而不是复制 React/Tailwind 参考代码。
2. `figma-use`：只读定位用户给出的素材节点、父级画板和页面结构；需要补 Figma 时才按增量写入流程执行。
3. Flutter 自动化：静态分析、Widget/Repository 测试和必要的 iOS 无签名构建。
4. Codex 子任务：按目录所有权并行开发，主控读取回报、做共享层整合并统一验收。
5. View 视觉审核：按用户最新要求暂停；只保留既有证据，不再启动审核任务或回写页面布局。

## 9. 本轮不伪造的外部缺口

- 登录/注册/注销与账号删除。
- 真实普通用户回复、实时 IM、推送、在线状态和音视频通话。
- UGC/真人认证审核后台、举报处理与申诉。
- 客服工单服务端、跨设备数据同步。
- App Store Connect 商品配置、服务端收据校验和生产法律 URL。

这些能力需要后端协议、运营配置或产品决策后进入 1.1，不阻塞 1.0 本地业务骨架验收。
