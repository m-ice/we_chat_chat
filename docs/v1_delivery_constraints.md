## 代码与文件所有权

- 用户当前首页、`main.dart`、`pubspec.yaml` 和现有公共封装是受保护基线；只允许主控做经过校验的增量集成。
- 子任务只修改被分配的模块目录与专属资源目录，不同时编辑路由、依赖注入、翻译或公共资源索引。
- 新页面沿用 GetX 的 route → binding → controller → repository 分层。View 不直接读写 `SharedPreferences`。
- 共享集成文件由主控串行合并，避免并行保存覆盖。

## UI 实现规则

- 以 375×812 为视觉验收基准，同时验证窄屏、长文本和键盘弹起。
- 装饰背景可以使用 `Stack`；变化内容必须使用 `Column`、`ListView`、`Sliver`、`Wrap`、`Expanded` 等流式布局。
- 图片统一走 `AppImage`，资源路径集中到 `AppImageString`；矢量/操作图标放 `assets/icons/<module>`，照片/背景放 `assets/images/<module>`。
- 可刷新列表统一使用 `AppRefreshView`，操作反馈统一使用 `AppToast`。
- 首页、广场的发布浮层统一使用 `CommonDraggableFloatWidget`，由持有页面负责关闭事件流。
- IM 数据和 UI 分别使用 `flutter_chat_core`、`flutter_chat_ui`，通过 theme/builders 适配设计，不自建完整聊天列表。
- 页面文案必须来自 `AppTranslations`，禁止在新业务 View 中新增散落的中英文判断。

## 数据与 UGC 约束

- 本地示例账号必须标记 `isSeedData/source=demo/moderationStatus=approved`，不可显示为真实认证或实时在线用户。
- 用户新发布内容默认 `pending`，只在自己的发布记录中可见；公开流仅展示 `approved`。
- 举报、客服请求先进入可持久化投递队列。真实 API 未接入前必须明确“本机保存待发送”，不能提示已经人工受理。
- 屏蔽与拉黑必须即时从推荐、搜索、视频和消息入口中移除目标。
- 真人认证不得把姓名、身份证号、手机号和证件照明文保存在本地；没有安全后端时不开放入口。
- 演示语音呼叫不得扣币；接入真实 RTC、对端状态和通话记录后才能收费。

## iOS 权限与发布门槛

- 当前只使用用户主动选图，因此只声明 `NSPhotoLibraryUsageDescription`，并提供中英文用途说明。
- 未实际使用相机、录音、定位时不得提前声明对应权限。
- 上线前仍需补齐：HTTPS 法务地址与真实运营主体、18+ 首启确认、举报/客服真实送达与处理 SLA、服务端购买票据校验、账号与关联 UGC 删除（若启用账号）。
- Archive 后依据 Xcode Privacy Report 填写应用级 Privacy Manifest 和 App Store Privacy Labels，不预填未发生的数据采集。

## 验收门槛

- `dart format`、`flutter analyze`、单元/Widget 测试、iOS device 无签名构建和 iOS Simulator build 全部通过。
- 独立 View 审核已按用户 2026-09-04 的最新要求暂停；本轮不得为了旧审核结论恢复或重排用户调整后的布局。
- P0 必须为 0；P1 应在交付前清零，不能清零的合规差异必须在报告中说明。
